# Практики занятия 1.3

Подготовлены проекты для Raspberry Pi Pico (RP2040):

| Практики | Проект | Функции |
| --- | --- | --- |
| 1.3.1–1.3.2 | `131-hello-usb` | `Hello, world!` через USB CDC раз в секунду |
| 1.3.3–1.3.4 | `133-led-button-usb` | Кнопка GPIO15 с подтяжкой к питанию; светодиод GPIO25; команды `e`, `d` |
| 1.3.5–1.3.7 | `134-led-module` | Модули led, logging, device; команды `e`, `d`, `v`, `i` |

Нажатие кнопки соответствует низкому уровню GPIO15. Нажатие подтверждается двумя выборками низкого уровня с интервалом 20 мс; одна выдержка ограничивает частоту опроса USB приблизительно 50 Гц. Состояние светодиода изменяется по переходу в подтверждённое нажатие.

## Проверка на плате

1. Установить зависимость: `python -m pip install -r requirements.txt`.
2. Удерживая BOOTSEL, подключить Pico и скопировать соответствующий файл UF2 из папки `build` проекта на диск RPI-RP2.
3. Закрыть терминал COM-порта и запустить нужный `check-1-3-N.py`. Скрипт ищет USB VID:PID `2e8a:000a` и сохраняет лог рядом с собой.
4. Для 1.3.2 записать прошивку 131; для 1.3.3 и 1.3.4 — 133; для 1.3.6 и 1.3.7 — 134.
5. При проверке 1.3.3 нажимать кнопку по приглашению скрипта. Это действие требует человека.
6. Сохранить реальные `device-1-3-N.log` в репозитории и запустить соответствующие проверки во вкладке GitHub Actions.

Файлы запуска всех семи проверок расположены в `.github/workflows` и вызывают проверки курса `ant-lab-ru/es-test`. Аппаратные логи не заменяются образцами из учебника.

## Порог журналирования

По умолчанию `LOG_LEVEL=3`. Для сравнения используется отдельная сборка с `-DLOG_LEVEL=2`: сообщения `dbg` удаляются при компиляции; команда `v` продолжает работать. Функциональная проверка вывода требует платы.

## Результаты локальной проверки

Все три проекта собраны в UF2. В итоговой сборке размер секции text составляет 37196 байт при LOG_LEVEL=3 и 37140 байт при LOG_LEVEL=2: снижение на 56 байт. Синтаксис пяти Python-скриптов проверен. Проверка обмена по USB, получение аппаратных логов и прогоны GitHub Actions ещё не выполнены.

Официальные проверки курса запущены локально. Проверки исходного кода всех семи заданий проходят; ошибки в 1.3.2, 1.3.3, 1.3.4, 1.3.6, 1.3.7 относятся только к отсутствию аппаратных логов. Сборки проверены отдельно установленным Arm GNU Toolchain.

Проверки 1.3.1 и 1.3.5 автоматически запускаются при отправке изменений соответствующих проектов в main. Остальные проверки оставлены для ручного запуска после получения логов.

pyserial 3.5 установлен локально в игнорируемую папку build/python-packages. Для запуска проверки из корня es-student: `powershell -ExecutionPolicy Bypass -File .\Run-DeviceCheck.ps1 -Task 1.3.2` (номер задания можно заменить). На момент проверки подключённая Pico не обнаружена ни среди последовательных портов, ни среди USB-устройств с VID 2e8a. Для получения логов требуется физическое подключение платы и запись соответствующей прошивки; для 1.3.3 — шесть нажатий кнопки.
